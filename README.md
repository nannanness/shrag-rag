# shrag-rag

上交所 100 家上市公司 2025 年年报的检索问答系统，语料 24224 页。

仓库自带 100 份 PDF（356 MB）和采集元数据，clone 下来就能跑完整流程。
采集代码在另一个仓库 `shrag`，已冻结，不再改动。

## 状态

八个阶段都跑通了，全量数据已入库。

| 阶段 | 结果 |
| --- | --- |
| 采集 | 100 家 2025 年报 |
| 解析 | MinerU，100/100 |
| 抽取 | 2828 个指标观测值 |
| 切片 | 59976 个 chunk |
| 索引 | text-embedding-v4 + FAISS，全量完成 |
| 检索 | top-1 80.6%，top-5 100% |
| 问答 | 带引用，支持跨公司排序 |
| 评测 | 1090 题，从指标表反推生成 |

还带一个本机 Web 界面（流式问答 + 指标浏览），见下面的「Web 界面」。

## 用法

```bash
git clone https://github.com/nannanness/shrag-rag.git
cd shrag-rag
pip install -r requirements.txt
```

需要两个 key，放 User 级环境变量即可：

```
MINERU_API_KEY     解析用      https://mineru.net
DASHSCOPE_API_KEY  嵌入和问答   https://bailian.aliyun.com
```

脚本先读进程环境变量，读不到再去 User 作用域取。

```bash
python scripts/06_index.py --limit 10    # 先建 10 家试一下，约 1 元
python scripts/09_ask.py -q "白云机场2025年的营业收入是多少"
python scripts/08_eval.py                # 自动评估检索
```

## Web 界面

```bash
python -m uvicorn web.app:app --host 127.0.0.1 --port 8000
```

打开 http://127.0.0.1:8000 。两个页签：问答和指标浏览。

索引启动时加载一次，常驻约 1.3 GB，所以**不要开多 worker，也不要 `--reload`** ——
每次热重载都要重新读 234 MB 的 faiss 索引。实测冷启动 1.3 秒，BM25 放后台线程
预热约 3 秒；问答首帧 1.5 秒、首字 2.2 秒，整题 5 秒左右。

问答接口是一个 SSE 流，先推 `meta`（意图、已核实数值、证据列表），再推 `delta`
（答案增量），最后 `done`（引用）。页面因此可以先把证据画出来，不用等模型生成完。

其余常用命令：

```bash
python scripts/06_index.py --limit 0 --workers 8          # 全量嵌入，约 51 分钟
python scripts/06_index.py --rebuild-only                 # 只重建 FAISS
python scripts/07_search.py -q "..." --compare            # 检索消融对比
python scripts/08_eval.py --metric 净利润 --show-fail 20
python scripts/09_ask.py -q "哪家净利润最高" --evidence
python tests/test_spec.py && python tests/verify_merge.py # 回归测试
```

## 结构

```
shrag_rag/          纯逻辑，不写文件，可单独 import
  spec.py           指标口径和文本工具的唯一来源
  parse/            解析
  extract/          指标抽取
  chunk/            切片
  index/            嵌入和向量库
  retrieve/         检索和重排
  answer/           问答和引用
scripts/            流程编排和 IO，01 到 09
web/                Web 服务，只做 HTTP 和静态资源
  app.py            SSE 问答 + 指标浏览接口
  static/           单页前端，无需构建
tests/              test_spec.py、verify_merge.py
data/
  pdfs/<代码>/      100 份年报
  meta/             采集元数据、解析清单、质量报告
  metrics/          结构化指标表
```

`shrag_rag` 里没有一行写文件，IO 全在 `scripts` 和 `web`，所以库好测。换解析器只要加个 adapter。

## 设计

层与层之间只有两个数据结构。

`ParsedDoc` / `Block` 是解析层输出：

```python
Block(kind, page_idx, text, html, bbox, ...)
kind ∈ {text, heading, table, image}
```

页眉页脚在解析层就丢掉，MinerU 把它们标成独立类型。表格保留 HTML，不是 Markdown。
这一层不暴露 MinerU 细节，换解析器只要加 adapter。

`MetricValue` 是抽取层输出：

```python
MetricValue(code, name, metric, year, value, unit, label, page, source)
```

`source` 是 summary 或 statement，`unit` 是金额单位。排序和展示都要用 `unit`。

### 双通道

财报最典型的问法是「哪家净利润最高」，这种问题跟任何一段文本都不相似，纯向量检索答不了。
所以数值类问题走结构化通道，文本类问题走检索。

| 问题 | 走哪条 |
| --- | --- |
| 亚盛集团 2025 年营业收入 | 结构化，注入已核实值 |
| 哪家净利润最高 | 结构化，查表排序 |
| 华能国际的审计机构 | 文本，向量 + BM25 |
| 浦发银行的经营策略重点 | 文本 |
| 净利润为什么下降 40% | 两路联合 |

结构化通道的底气来自年报的「主要会计数据 / 主要财务指标」表：行标签全国统一，列就是年份，
一张表给出三年数据。这张表本身还是标准答案，评测集就是从它反推的。

### 关键参数

| 位置 | 参数 | 值 |
| --- | --- | --- |
| `chunk/chunker.py` | `FLUSH_LEVEL` | 2 |
| `answer/qa.py` | 融合权重 | 1.0 × 向量 + 0.3 × BM25 + 重排 |
| `retrieve/rerank.py` | 加分规则 | 只认首个命中 |

## 踩过的坑

改代码前先看这里，都是踩出来的。

采集（`shrag` 仓库）

- 查询接口不需要 cookie，带与不带返回字节完全相同
- PDF 有 `acw_sc__v2` 挑战，密钥在页面里，要现场算 cookie 重放
- 别用文件名判断报告类型，看 `BULLETIN_TYPE`
- `BULLETIN_YEAR` 2021 年改了语义，之前是报告年份，之后是公告年份
- HTTP 206 必须放行，只放行 200 会让 Range 探大小静默降级

MinerU

- 单文件 200 页上限，本批 75% 超限，先本地拆片，解析完按页偏移合并
- 批大小上限 10
- token 密度 0.7101 tokens/字符，真调样本读 usage 标定，别按字符估
- 瓶颈是单请求延迟不是 TPM，串行时 TPM 只用掉 5%，8 并发后 2.4 到 22.7 条/秒
- `qwen-turbo-latest` 返回 403，用 `qwen-plus` 或 `qwen-turbo`

FAISS

- 向量必须 L2 归一化。`IndexFlatIP` 不归一化算的是模长乘相似度，实测能把无关结果顶到 7.543 分
- 索引路径必须纯 ASCII。写中文文件名 faiss 不报错，但写到乱码名（`_中文.faiss` 变成 `_涓枃.faiss`）。写中文目录才会报错

解析

- MinerU 把所有标题都标成 `text_level=2`，层级要按文本编号推，不能信 `text_level`
- 正文句子也会以「一、二、三、」开头，用句读特征挡：标题不含 `。；，！？`，剥掉序号后不超过 40 字
- `√适用 □不适用` 会被判成 heading，一度变成最大的章节，现在有正则挡
- 有些标题被标成 `text`，比如 600108 的「合并现金流量表」，定位报表不能靠标题
- 行标签常带中文序号，「三、利润总额」「①货币资金」都要能匹配，但阿拉伯数字必须带分隔符才剥，否则会吃掉「1年以内」
- 银行年报写法不同，用「本行」不用「母公司」，用「股东权益」不用「所有者权益」
- 空的 `table_body` 多是跨页表的重复检出
- 金额单位是文档级声明，可能只在 p23 出现一次而数据在 p121，局部表格还会覆盖它。只在 80 块窗口内取最近声明，超出就回退全文最常见单位，不处理总资产会差 100 倍
- 切片只在 ≤2 级标题处断，表格不切断文本，允许跨小节合并碎片。不加这三条中位数只有 72 字，加了是 255
- 「主要会计数据」表中间会再出现一次表头，资产类用「年末」利润类用「年」，列到年份的映射要边走边更新

抽取

- `_fill_from_statements` 里一个 `break` 位置错了，导致每张表只记一个指标，放弃含正确值的表。修之前中国石化经营现金流抽成 -3,280,213（真值 162,496 百万元），招商银行利润总额 -259（真值 178,993 百万元）
- 单位声明还有「（人民币百万元，特别注明除外）」这种写法，只认「单位：」会把 178,993 标成「元」，差 100 万倍
- statement 来源的值必须出现在本次检索到的证据里才注入 prompt，否则会和证据矛盾
- 跨公司排序先折成同单位，上汽写「元」浦发写「百万元」，直接比大小是错的
- 可用于排序的家数不足时要声明范围，曾经在只有 84 家可排序时答成「100 家中最高」

检索

- 纯向量答不了「某公司某指标是多少」，叙述性文字会把财务表挤下去，白云机场营业收入一度排到第 80。用 `metrics` 元数据预过滤后降到第 2
- 加分规则只认首个命中，否则「近三年主要会计数据」会同时命中「主要会计数据」，叠成 +0.65，把无关章节顶上来
- 联营、合营、子公司的表也含指标，同样会拿到加分，把本公司数据挤下去
- 主题正则不能太宽，「经营情况讨论」是父级章节名，底下有党建小节，会把「主要业务」挤到第 2
- 口语别名必须有。问「扣非归母净利润」而别名只有官方全称时，会被更短的「净利润」抢先匹配，整类 0/9；光加官方全称不够，裸的「归母净利润」也得有

评测

- 别用字符串比数值。浦发以百万元为单位写 `173,964`，期望串是 `173,964.00`，差一个 `.00` 就判错，而正确 chunk 其实排第 1。改按数值比对后 top-1 从 50.9% 升到 79.6%
- 用例要从指标表反推，手写 10 条会过拟合
- 跑 `08_eval.py` 看汇总行，别看退出码。jieba 往 stderr 打日志会让 PowerShell 报错，退出码可能非 0

工程

- `TextEmbedding.call` 不传 `api_key` 时只认环境变量。`get_api_key` 会兜底读 User 变量，于是出现最迷惑的失败：key 拿到了却报 `No api key provided`
- `Set-Content -Encoding UTF8` 会写 BOM，带 BOM 的 `.py` 直接语法错。但 CSV 的 BOM 是故意的，为了 Excel 能打开中文
- 别用暂存目录写完再拷回项目，拷贝会覆盖已经改好的文件
- Python 3.13 没有 `Path.is_ascii()`

## 已知问题

1. 银行类年报指标覆盖偏低，民生 6/12、招商 7/12，模板差异，不是 bug
2. **报表兜底抽取仍有单位标错**，做 Web 时查出来的。1185 个单元格里 17 个量级明显不对，例如：
   北方稀土营业收入抽成 `29.11 元`、杭钢股份营业收入 `-17.81 元`、
   保利发展净利润 `5,022,154,432.21 万元`（数值其实是元，放大一万倍）。
   覆盖率是 100%，但不等于正确。目前只在展示层标「?」提示核对，根因还在抽取层的单位判定
3. `metrics_wide.csv` 里仍有少量错值，只用于评测和排序，不要当权威数据引用
4. `data/parsed/` 占 5.8 GB，`scripts/04_prune.py` 能清到 316 MB，默认 dry-run，暂时没跑
5. 表格 chunk 只有 6% 关联到财务指标，其余是业务类表格
6. 超长表格按 12000 字截断，理想做法是换摘要
7. top-1 是 80.6%，没继续调。top-5 已经 100%，在同一批数据上再调只会过拟合
8. 公司名匹配不认简称和集合称谓，「浦发」「四大行」这类问法答不了
9. 扣非加权平均净资产收益率缺出题模板，这 95 家能否检索到没有实测证据
10. 净利润是唯一没有标准表来源的指标（98 条全部来自报表兜底），跨公司排序用它时要带来源说明
11. Web 端没有鉴权，只适合本机使用；挂公网会被刷 LLM 额度

## 版本控制

入库：`shrag_rag/`、`scripts/`、`tests/`、`diagnostics/`、`configs/`、`data/pdfs/`、`data/meta/`、`data/metrics/`。

不入库：`data/parsed/`（5.8 GB）、`data/index/`、`data/chunks/`（121.8 MB）、`logs/`。

`data/index/manifest.json` 存了 `chunks.jsonl` 的 sha256 前 16 位，用来检测漂移：切片重跑过而索引没重建时，哈希对不上会报错。
