# shrag-rag —— 上交所年报 RAG 系统

针对 **100 家上交所上市公司 2025 年年度报告**（24224 页）构建的检索增强问答系统。

> **本仓库自包含**：100 份年报 PDF（356 MB）与采集元数据已随仓库提交，
> `git clone` 即可复现全部流程，不依赖外部项目。

## 二、架构

### 分层

```
shrag-rag\
├── shrag_rag\              库：纯逻辑，**不含任何 IO**，可 import 可测
│   ├── spec.py             ★ 指标口径与文本工具的唯一来源
│   ├── parse\              ② 解析
│   ├── extract\            ③ 抽取
│   ├── chunk\              ④ 切片
│   ├── index\              ⑤ 嵌入 + 向量库
│   ├── retrieve\           ⑥ 检索与重排
│   └── answer\             ⑦ 问答与引用
├── scripts\                编排：只做 IO 与流程
│   ├── 01_parse.py         拆片→提交→轮询→合并→落盘
│   ├── 02_inspect.py       解析质量验证 + 人眼比对导出
│   ├── 03_metrics.py       指标抽取
│   ├── 04_prune.py         清理中间产物（默认 dry-run）
│   ├── 05_chunk.py         章节感知切片
│   ├── 06_index.py         嵌入 + 建 FAISS 索引（可断点续跑）
│   ├── 07_search.py        检索 CLI（含消融对比）
│   ├── 08_eval.py          自动评估（用指标表反推问题）
│   └── 09_ask.py           带引用的问答 CLI
├── tests\                  回归测试
│   ├── test_spec.py        43 个断言：口径定义 / 序号剥离 / 数字解析
│   └── verify_merge.py     分片合并的页码偏移
├── diagnostics\            排查过程留下的一次性脚本（后端对比等）
└── data\
```

**为什么坚持库/脚本分层**：`shrag_rag/` 里没有一行写文件，全部 IO 在 `scripts/`。
所以库是纯函数式的、好测；后续每个阶段都能 `from shrag_rag.parse import ParsedDoc`
直接复用，不必复制粘贴。

### 数据契约（架构核心）

整个系统只有两个关键数据结构，是层与层之间的接口：

**`ParsedDoc` / `Block`**（解析层输出）
```python
Block(kind, page_idx, text, html, bbox, ...)
  kind ∈ {text, heading, table, image}
```
- **页眉页脚在解析层就丢掉** —— MinerU 把 `page_number`/`header` 标成独立类型。
  它们没有检索价值，却会污染切片（朴素抽取会产出 `48/134二、财务报表` 这种粘连串）
- **表格保留 HTML** —— MinerU 输出 `<table><td>` 而非 Markdown，
  任何"按 `|` 切分"的想法都是错的
- **这一层不暴露任何 MinerU 细节**，换解析器只需加一个 adapter

**`MetricValue`**（抽取层输出）
```python
MetricValue(code, name, metric, year, value, unit, label, page, source)
```

### 双通道设计（核心判断）

来自一个实测结论：

> 财报最典型的提问「**哪家净利润最高**」跟任何一段文本都不相似，
> **纯向量检索在原理上答不了**。

| 问题类型 | 例子 | 走哪条 |
| --- | --- | --- |
| 数值 | 亚盛集团2025年营业收入 | **结构化**（注入已核实值） |
| 排序对比 | 哪家净利润最高 | **结构化**（查表排序） |
| 事实 | 华能国际的审计机构 | 文本（向量+BM25） |
| 定性 | 浦发银行的经营策略重点 | 文本 |
| 归因 | 净利润为什么下降40% | 两路联合 |

事实依据：年报「主要会计数据 / 主要财务指标」是**强制标准化披露**的 ——
行标签全国统一，且**列就是年份**，一张表直接给出三年数据。

**额外收益**：这张表本身是**标准答案**，可自动生成带 ground truth 的评估集
（`scripts/08_eval.py` 就是这么做的）。

## 四、实测标定的约束（**全部写进了代码**）

### 采集侧（`shrag` 仓库）

1. **查询接口不需要 cookie** —— 带与不带返回字节完全相同
2. **PDF 受 `acw_sc__v2` JS 挑战保护** —— 6 种请求头组合实测无效；
   密钥以 base64 明文躺在挑战页里，需现场算出 cookie 重放
3. **PDF 链接换过四代** —— 绝不能用文件名判断报告类型，要用 `BULLETIN_TYPE`
4. **`BULLETIN_YEAR` 在 2021 年变了语义** —— 之前是报告年份，之后是公告年份
5. **HTTP 206 必须放行** —— Range 请求探文件大小，只放行 200 会导致静默降级

### MinerU 侧

6. **单文件 200 页上限** —— 本批年报页数中位数 234，**75% 超限**
   （100 份 → 177 个请求）。超限的先本地拆片，解析完按页偏移合并
7. **批大小上限 10** —— 传 25 报 `batch size is invalid`
8. **token 密度 0.7101 tokens/字符** —— 真调样本读 usage 标定，
   不能按字符估（本批中文仅占 46.1%）
9. **瓶颈是单请求延迟，不是 TPM** —— 串行时每次约 4 秒而 TPM 只用掉 <5%；
   改 8 并发后 **2.4 → 22.7 条/秒**
10. **`qwen-turbo-latest` 返回 403** —— 用 `qwen-plus` / `qwen-turbo` / `qwen-flash`

### FAISS 侧

11. **向量必须 L2 归一化** —— `IndexFlatIP` 不归一化时算的是「模长×相似度」。
    实测把向量同方向放大 10 倍，它得分 7.543（>1）并把真正的最优结果
    （0.759）挤到第二
12. **索引路径必须纯 ASCII** —— 写中文文件名时 faiss **不报错，但写到乱码名**
    （`_中文.faiss` → 实际生成 `_涓枃.faiss`）。写中文**目录**才会正常报错

### 解析数据侧

13. **MinerU 把所有标题都标成 `text_level=2`** —— 「第一节 释义」与「一、 释义」
    会变成同级。层级必须按**文本编号模式**推断，不能信 `text_level`
14. **正文句子会以「一、二、三、」开头** ——
    `三、 大信会计师事务所…出具了标准无保留意见的审计报告。` 按编号模式会被
    误判成标题。用**句读特征**挡（标题不含 `。；，！？`，剥序号后 ≤40 字）
15. **勾选框行会被判成 heading** —— `√适用 □不适用` 一度成为"最大章节"（10766 个 chunk）
16. **有些标题被标成 `text` 而非 `heading`** —— 如 600108 的「合并现金流量表」。
    定位报表**不能靠标题**
17. **行标签常带中文序号** —— 「三、利润总额」「一、营业收入」「①货币资金」
    都要能匹配；但阿拉伯数字**必须带分隔符**才剥，否则会吃掉「1年以内」
18. **银行类年报结构不同** —— 标题写作「合并资产负债表和资产负债表」；
    用「本行」而非「母公司」；用「股东权益」而非「所有者权益」
19. **空 `table_body` 多为跨页表的重复检出** —— MinerU 会把跨页表合并成一个
    大块（600108 合并资产负债表 105 行），另留空的重复块
20. **金额单位是文档级声明** —— 「单位：百万元」可能只在 p23 出现一次，
    而数据在 p121。且**局部表格会覆盖它**（浦发 p139 是「亿元」）——
    只在 80 块窗口内取最近声明，超出则回退到全文最常见单位
    **否则总资产会差 100 倍**

### 检索侧

21. **纯向量答不了「某公司某指标是多少」** —— 叙述性文字把财务表挤下去
    （白云机场营业收入排第 80）。用 `metrics` 元数据预过滤后降到第 2
22. **加分规则会重复计数** —— `近三年主要会计数据` 同时命中「主要会计数据」，
    叠成 +0.65，把无关的财务汇总节顶到业务描述之上
23. **联营/合营/子公司的表也是"财务表且含指标"** —— 同样拿到加分，
    会把本公司数据挤下去
24. **主题正则不能太宽** —— `经营情况讨论` 是父级章节名，其下有党建/安全小节，
    导致「主要业务」第 1 名变成「（六）党建引领」
25. **口语别名必须有** —— 问「扣除非经常性损益后的**归母**净利润」而别名只有
    官方全称时，会被更短的「净利润」抢先匹配，该指标整类 0/9

### 评测侧

26. **不能用字符串比数值** —— 浦发以**百万元**为单位，年报写 `173,964`
    而期望串是 `173,964.00`，差一个 `.00` 就判错。**那是评测错了，不是检索错了**
    （正确 chunk 其实排第 1）。改按数值比对后 top-1 从 50.9% → 79.6%

### 检索评估（自动生成用例）

| 方案 | top-1 | top-5 |
| --- | --- | --- |
| 纯向量 | 3/10 | 6/10 |
| 向量+BM25（无路由无重排） | 7/10 | 9/10 |
| 完整（路由+重排） | **10/10** | 10/10 |
| **完整（100 家，1090 题自动集）** | **879/1090 (80.6%)** | **1090/1090 (100%)** |

**100 家规模没有衰减**（10 家时 79.6% / 100%）。11 个指标全部 100%。
**top-5 100% 是 RAG 的关键指标** —— 生成阶段看到的是 top-5，答案必定在其中。

评估用例是**用指标表反推**出来的（`scripts/08_eval.py`）：
每个「公司 + 指标 + 实测值」自动构成一道题，标准答案就是那个数，
**不是我编的**，所以不会在 10 条手写用例上过拟合。

全部正确并带引用。模型的**自发交叉验证**：

                   = 173,964，进一步确认无误"

跨公司题主动排除了白云机场（已改聘致同，立信只是其历史审计机构）。

## 六、目录与版本控制

**入库的**（小而有价值）：
- `shrag_rag/` `scripts/` `tests/` `diagnostics/` `configs/`
- `data/pdfs/` 100 份 PDF（356 MB）
- `data/meta/` 采集元数据、解析清单、质量报告

**不入库的**（大且可重建）：
- `data/parsed/` 解析产物（5.8 GB，含 MinerU 原始 zip 等）
  → 可用 `scripts/04_prune.py` 清到 316 MB（默认 dry-run）
- `data/index/` 向量索引与嵌入缓存
- `data/chunks/` 切片（121 MB）
- `logs/`

`data/index/manifest.json` 里存了 `chunks.jsonl` 的 sha256，
**用于检测漂移** —— 若切片重跑过而索引没重建，哈希对不上就报错。

## 七、已知缺口（如实记录）

1. **银行类年报指标覆盖偏低**（民生 6/12、招商 7/12）—— 模板差异，非 bug
2. **`source=statement`（报表兜底）已修好，但仍受双闸约束** ——
   曾经出过严重错值（中国石化经营现金流抽成 -3,280,213，真值 162,496 百万元；
   招商银行利润总额抽成 -259，真值 178,993 百万元）。
   根因是 `_fill_from_statements` 里一个 `break` 位置错了 ——
   每张表只记录**一个**指标，于是放弃了含正确值的表、退到解析错位的表。
   现在遍历整表所有行 + 候选表逐个尝试 + 单位声明识别放宽到括号写法。
   **并且加了一道安全闸**：statement 来源的值必须**出现在本次检索到的证据里**
   才注入 prompt，避免又注入了与证据矛盾的数。
   ⚠️ `data/metrics/metrics_wide.csv` 可作评测标准答案，但已知仍有少量错值。
3. **`data/parsed/` 占 5.8 GB** —— 已提供清理脚本，但需要时手动跑
4. **表格 chunk 仅 6% 关联到财务指标** —— 其余是业务类表格
5. **超长表格按 12000 字截断** —— 理想做法是换摘要
6. **检索 top-1 为 80.3%（100 家规模）** —— 未继续调，因为 top-5 已 99.8%，
   而继续在同批数据上调只会过拟合
7. **公司名匹配未处理简称与集合称谓** —— 「浦发」这类简称、
   「四大行」这类集合词都认不出
