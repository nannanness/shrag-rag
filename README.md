# shrag-rag —— 上交所年报 RAG 系统

针对 **100 家上交所上市公司 2025 年年度报告**（24224 页）构建的检索增强问答系统。

> **本仓库自包含**：100 份年报 PDF（356 MB）与采集元数据已随仓库提交，
> `git clone` 即可复现全部流程，不依赖外部项目。
> 采集侧代码在另一个仓库 `shrag`（已冻结，不再改）。
> **新会话请先读 [`RESUME.md`](RESUME.md)** —— 那是一页纸的续跑指引。

## 二、架构

### 分层

```
shrag-rag\
├── shrag_rag\              库：纯逻辑，**不含任何 IO**，可 import 可测
│   ├── spec.py             ★ 指标口径与文本工具的唯一来源
│   ├── parse\              ② 解析
│   ├── extract\            ③ 抽取
│   ├── chunk\              ④ 切片
│   ├── index\              ⑤ 嵌入 + 向量库
│   ├── retrieve\           ⑥ 检索与重排
│   └── answer\             ⑦ 问答与引用
├── scripts\                编排：只做 IO 与流程
│   ├── 01_parse.py         拆片→提交→轮询→合并→落盘
│   ├── 02_inspect.py       解析质量验证 + 人眼比对导出
│   ├── 03_metrics.py       指标抽取
│   ├── 04_prune.py         清理中间产物（默认 dry-run）
│   ├── 05_chunk.py         章节感知切片
│   ├── 06_index.py         嵌入 + 建 FAISS 索引（可断点续跑）
│   ├── 07_search.py        检索 CLI（含消融对比）
│   ├── 08_eval.py          自动评估（用指标表反推问题）
│   └── 09_ask.py           带引用的问答 CLI
├── tests\                  回归测试
│   ├── test_spec.py        43 个断言：口径定义 / 序号剥离 / 数字解析
│   └── verify_merge.py     分片合并的页码偏移
├── diagnostics\            排查过程留下的一次性脚本（后端对比等）
└── data\
```

**为什么坚持库/脚本分层**：`shrag_rag/` 里没有一行写文件，全部 IO 在 `scripts/`。
所以库是纯函数式的、好测；后续每个阶段都能 `from shrag_rag.parse import ParsedDoc`
直接复用，不必复制粘贴。

### 数据契约（架构核心）

整个系统只有两个关键数据结构，是层与层之间的接口：

**`ParsedDoc` / `Block`**（解析层输出）
```python
Block(kind, page_idx, text, html, bbox, ...)
  kind ∈ {text, heading, table, image}
```
- **页眉页脚在解析层就丢掉** —— MinerU 把 `page_number`/`header` 标成独立类型。
  它们没有检索价值，却会污染切片（朴素抽取会产出 `48/134二、财务报表` 这种粘连串）
- **表格保留 HTML** —— MinerU 输出 `<table><td>` 而非 Markdown，
  任何"按 `|` 切分"的想法都是错的
- **这一层不暴露任何 MinerU 细节**，换解析器只需加一个 adapter

**`MetricValue`**（抽取层输出）
```python
MetricValue(code, name, metric, year, value, unit, label, page, source)
```
`source ∈ {summary, statement}`；`unit` 是金额单位（元/万元/百万元），**排序与展示必须用它**。

### 双通道设计（核心判断）

来自一个实测结论：

> 财报最典型的提问「**哪家净利润最高**」跟任何一段文本都不相似，
> **纯向量检索在原理上答不了**。

| 问题类型 | 例子 | 走哪条 |
| --- | --- | --- |
| 数值 | 亚盛集团2025年营业收入 | **结构化**（注入已核实值） |
| 排序对比 | 哪家净利润最高 | **结构化**（查表排序） |
| 事实 | 华能国际的审计机构 | 文本（向量+BM25） |
| 定性 | 浦发银行的经营策略重点 | 文本 |
| 归因 | 净利润为什么下降40% | 两路联合 |

事实依据：年报「主要会计数据 / 主要财务指标」是**强制标准化披露**的 ——
行标签全国统一，且**列就是年份**，一张表直接给出三年数据。

**额外收益**：这张表本身是**标准答案**，可自动生成带 ground truth 的评估集
（`scripts/08_eval.py` 就是这么做的）。

### 关键参数（改这些之前先读第四节）

| 位置 | 参数 | 值 | 为什么是这个值 |
| --- | --- | --- | --- |
| `chunk/chunker.py` | `FLUSH_LEVEL` | 2 | 只在 ≤2 级标题处断章，见约束 21 |
| `answer/qa.py` | 融合权重 | `1.0×vec + 0.3×bm25 + rerank` | 池内 min-max 归一化 |
| `retrieve/rerank.py` | `SUMMARY_RULES` | 首个命中生效 | 重复计数会顶掉正确结果，见约束 27 |
| `spec.py` | `CORE_METRICS` | 7 个 | 覆盖率 100% 的那 7 个 |
| `index/embedder.py` | `workers` / `batch` | 8 / 10 | batch 10 是硬上限，见约束 7 |
| `pdfsplit.py` | `DEFAULT_MAX_PAGES` | 195 | MinerU 200 页上限留余量，见约束 6 |

## 三、快速开始

```bash
git clone https://github.com/nannanness/shrag-rag.git
cd shrag-rag
pip install -r requirements.txt

# 需要两个环境变量（User 级即可，脚本会自动去 User 作用域兜底读）
#   MINERU_API_KEY     https://mineru.net       解析用
#   DASHSCOPE_API_KEY  https://bailian.aliyun.com 嵌入与问答用

python scripts/06_index.py --limit 10    # 建 10 家试点索引（约 1 元）
python scripts/09_ask.py -q "白云机场2025年的营业收入是多少"
python scripts/08_eval.py                # 自动评估检索
```

常用命令：

```bash
python scripts/06_index.py --limit 0 --workers 8   # 全量嵌入（约 51 分钟）
python scripts/06_index.py --rebuild-only          # 只重建 FAISS，不重新嵌入
python scripts/07_search.py -q "..." --compare     # 检索消融对比
python scripts/08_eval.py --metric 净利润 --show-fail 20
python scripts/09_ask.py -q "哪家净利润最高" --evidence
python tests/test_spec.py && python tests/verify_merge.py   # 回归测试，须 exit 0
```

## 四、实测标定的约束（**全部写进了代码**）

> 这一节是本项目最贵的资产：每条都是踩出来的，附**可复现的反例**。
> 改代码前先在这里搜一下，避免把已经修好的坑再踩回去。

### 采集侧（`shrag` 仓库）

1. **查询接口不需要 cookie** —— 带与不带返回字节完全相同
2. **PDF 受 `acw_sc__v2` JS 挑战保护** —— 6 种请求头组合实测无效；
   密钥以 base64 明文躺在挑战页里，需现场算出 cookie 重放
3. **PDF 链接换过四代** —— 绝不能用文件名判断报告类型，要用 `BULLETIN_TYPE`
4. **`BULLETIN_YEAR` 在 2021 年变了语义** —— 之前是报告年份，之后是公告年份
5. **HTTP 206 必须放行** —— Range 请求探文件大小，只放行 200 会导致静默降级
   （600115 曾据此存下 0.3 MB 的桩文件，且**没有任何报错**）

### MinerU 侧

6. **单文件 200 页上限** —— 本批年报页数中位数 234，**75% 超限**
   （100 份 → 177 个请求）。超限的先本地拆片，解析完按页偏移合并
7. **批大小上限 10** —— 传 25 报 `batch size is invalid`
8. **token 密度 0.7101 tokens/字符** —— 真调样本读 usage 标定，
   不能按字符估（本批中文仅占 46.1%）
9. **瓶颈是单请求延迟，不是 TPM** —— 串行时每次约 4 秒而 TPM 只用掉 <5%；
   改 8 并发后 **2.4 → 22.7 条/秒**
10. **`qwen-turbo-latest` 返回 403** —— 用 `qwen-plus` / `qwen-turbo` / `qwen-flash`

### FAISS 侧

11. **向量必须 L2 归一化** —— `IndexFlatIP` 不归一化时算的是「模长×相似度」。
    实测把向量同方向放大 10 倍，它得分 7.543（>1）并把真正的最优结果
    （0.759）挤到第二
12. **索引路径必须纯 ASCII** —— 写中文文件名时 faiss **不报错，但写到乱码名**
    （`_中文.faiss` → 实际生成 `_涓枃.faiss`）。写中文**目录**才会正常报错。
    现在 `VectorStore` 里有 assert 挡这个

### 解析数据侧

13. **MinerU 把所有标题都标成 `text_level=2`** —— 「第一节 释义」与「一、 释义」
    会变成同级。层级必须按**文本编号模式**推断，不能信 `text_level`
14. **正文句子会以「一、二、三、」开头** ——
    `三、 大信会计师事务所…出具了标准无保留意见的审计报告。` 按编号模式会被
    误判成标题。用**句读特征**挡（标题不含 `。；，！？`，剥序号后 ≤40 字）
15. **勾选框行会被判成 heading** —— `√适用 □不适用` 一度成为"最大章节"（10766 个 chunk）。
    现在由 `_NOT_A_HEADING_RE` 挡
16. **有些标题被标成 `text` 而非 `heading`** —— 如 600108 的「合并现金流量表」。
    定位报表**不能靠标题**
17. **行标签常带中文序号** —— 「三、利润总额」「一、营业收入」「①货币资金」
    都要能匹配；但阿拉伯数字**必须带分隔符**才剥，否则会吃掉「1年以内」
18. **银行类年报结构不同** —— 标题写作「合并资产负债表和资产负债表」；
    用「本行」而非「母公司」；用「股东权益」而非「所有者权益」
19. **空 `table_body` 多为跨页表的重复检出** —— MinerU 会把跨页表合并成一个
    大块（600108 合并资产负债表 105 行），另留空的重复块
20. **金额单位是文档级声明** —— 「单位：百万元」可能只在 p23 出现一次，
    而数据在 p121。且**局部表格会覆盖它**（浦发 p139 是「亿元」）——
    只在 80 块窗口内取最近声明，超出则回退到全文最常见单位
    **否则总资产会差 100 倍**
21. **切片中位数会掉到 72 字** —— 三个原因叠加：见标题就断、遇表格就断、
    不跨小节合并。实测改为「只在 ≤2 级标题断 + 表格不断开文本 + 允许跨小节
    合并碎片」后中位数 **72 → 255**
22. **「主要会计数据」表中间会再出现一次表头** —— 资产类指标用
    `2025年末/2024年末`，利润类用 `2025年/2024年`，所以「列 → 年份」的映射
    必须**边走边更新**，只在第一行解析一次会串年份

### 抽取侧（statement 兜底）

23. **兜底路径里一个 `break` 放错位置会造成系统性错值** ——
    `_fill_from_statements` 原本**每张表只记录一个指标**，于是放弃了含正确值
    的表、退到解析错位的表。实测错成：
    中国石化经营现金流 `-3,280,213`（真值 `162,496` 百万元）、
    招商银行利润总额 `-259`（真值 `178,993` 百万元）。
    现在遍历整表所有行 + 候选表逐个尝试。
    ⚠️ **教训：`break` 写在双重循环里，一定要问"它到底断的是哪一层"**
24. **单位声明不能只认「单位：」** —— 招商银行写的是
    `（人民币百万元，特别注明除外）`，只认「单位：」会把 178,993 标成「元」，
    **差 100 万倍**。`declared_unit` 现在也接受「整块被括号包住」这种写法，
    同时用「块必须很短」防误判
25. **报表兜底值必须过证据闸** —— 修好抽取逻辑后仍可能抽到与检索证据矛盾的数。
    `RagQA.lookup_facts(min_source=None, corrob_hits=...)` 要求 statement 来源的值
    **出现在本次检索到的证据文本里**才注入 prompt
26. **跨公司排序必须归一化单位** —— 上汽 `960,207,461,450 元` 与浦发
    `10,081,746 百万元` 直接比大小是错的。`_UNIT_MUL` 先把各家值折成同单位
27. **覆盖不足时必须声明范围** —— 「哪家净利润最高」在只有 84 家可排序时
    曾答成"100 家中最高"。现在排名题强制带覆盖率说明

### 检索侧

28. **纯向量答不了「某公司某指标是多少」** —— 叙述性文字把财务表挤下去
    （白云机场营业收入排第 80）。用 `metrics` 元数据预过滤后降到第 2
29. **加分规则会重复计数** —— `近三年主要会计数据` 同时命中「主要会计数据」，
    叠成 +0.65，把无关的财务汇总节顶到业务描述之上。
    现在 `_first_match` 只认**首个**命中的规则
30. **联营/合营/子公司的表也是"财务表且含指标"** —— 同样拿到加分，
    会把本公司数据挤下去
31. **主题正则不能太宽** —— `经营情况讨论` 是父级章节名，其下有党建/安全小节，
    导致「主要业务」第 1 名变成「（六）党建引领」
32. **口语别名必须有** —— 问「扣除非经常性损益后的**归母**净利润」而别名只有
    官方全称时，会被更短的「净利润」抢先匹配，该指标整类 0/9。
    同理光加官方全称不够，**裸简称「归母净利润」也得有**（否则上汽那题直接拒答）

### 评测侧

33. **不能用字符串比数值** —— 浦发以**百万元**为单位，年报写 `173,964`
    而期望串是 `173,964.00`，差一个 `.00` 就判错。**那是评测错了，不是检索错了**
    （正确 chunk 其实排第 1）。改按数值比对后 top-1 从 50.9% → 79.6%
34. **评估集要用指标表反推** —— 手写 10 条会过拟合。`08_eval.py` 把
    「公司 + 指标 + 实测值」全量转成题目，标准答案不是人编的

### 答案生成侧

38. **`TextEmbedding.call()` 不传 `api_key` 时只认环境变量** ——
    `get_api_key()` 会兜底去读 Windows User 级变量，于是出现最迷惑的一种失败：
    **key 明明拿到了（116 字符），却报 `AuthenticationError: No api key provided`**。
    根因是 `DashScopeEmbedder` 里那个负责设 `dashscope.api_key` 的 `ds` 属性
    **定义了但从来没被引用过**（全仓库零调用）。
    对照 `llm.py` 是对的 —— 它在 `chat()` 里显式 `dashscope.api_key = self.api_key`，
    所以**只有嵌入路径坏、问答路径是好的**，更难发现。
    现在 `_embed_batch` 里显式设一次，并把死代码 `ds` 属性删掉。
    **教训：鉴权失败要追问「key 到底传给了谁」，而不是只看「key 有没有读到」**
39. **`08_eval.py` 的退出码不能当成功判据** —— jieba 往 stderr 打日志会让
    PowerShell 报 `NativeCommandError`，`$LASTEXITCODE` 因此可能非 0。
    看**汇总行**：`top-5 命中 == 题数` 才算通过

### 工程侧（踩过的坑，与业务无关但同样费时间）

35. **`Set-Content -Encoding UTF8` 会写 BOM** —— 带 BOM 的 `.py` 直接
    `invalid non-printable character U+FEFF` 语法错。
    **但 CSV 的 BOM 是故意的**（`utf-8-sig`，为了 Excel 能正常打开中文）
36. **不要用「暂存目录写文件再拷回项目」的做法** —— 拷贝会覆盖掉项目里
    已经改好的文件（`01_parse.py` 的自包含路径逻辑就这么被回退过一次）。
    新文件可以在暂存区起草，**已有文件一律直接改项目里的那份**
37. **Python 3.13 没有 `Path.is_ascii()`** —— 用 `str(path).isascii()`

`净利润` 的 100/100 是**算出来的**：年报模板在「归母净利润 = 净利润」时
常**只披露归母那一行**，所以 `METRICS` 里把 `净利润` 的兜底值取归母值。
**这属于口径假设，不是原始披露值** —— 引用时要知道这一点。

**90/100 家公司拿满 12 个指标**；其余分布 12:90 / 11:7 / 10:1 / 9:2。
最弱的是银行（民生、招商），属年报模板差异。
抽取来源：`summary` 2653 条、`statement` 175 条。

### 检索评估（自动生成用例，1090 题）

| 方案 | top-1 | top-5 |
| --- | --- | --- |
| 纯向量（10 家手写集） | 3/10 | 6/10 |

**100 家规模没有衰减**（10 家时 79.6% / 100%）。
自动评测覆盖 **11 个指标，全部 100%**；

（`scripts/08_eval.py:31`）—— 这是评测集的缺口，不是检索的问题，见第七节。
**top-5 100% 是 RAG 的关键指标** —— 生成阶段看到的是 top-5，答案必定在其中。

## 六、目录与版本控制

**入库的**（小而有价值）：
- `shrag_rag/` `scripts/` `tests/` `diagnostics/` `configs/`
- `data/pdfs/<代码>/` 100 份 PDF（356.3 MB，每家一个子目录，目录名是股票代码）
- `data/meta/` 采集元数据、解析清单、质量报告
- `data/metrics/` 结构化指标表

**不入库的**（大且可重建）：
- `data/parsed/` 解析产物（5.8 GB，含 MinerU 原始 zip 等）
  → 可用 `scripts/04_prune.py` 清到 316 MB（默认 dry-run，**尚未执行**）
- `data/index/` 向量索引与嵌入缓存（`vectors.faiss` 245.7 MB）
- `data/chunks/` 切片（`chunks.jsonl` 121.8 MB）
- `logs/`

`data/index/manifest.json` 里存了 `chunks.jsonl` 的 sha256 前 16 位，
**用于检测漂移** —— 若切片重跑过而索引没重建，哈希对不上就报错。

**推送成功的判据**：GitHub 偶尔连不上，`push` 与 `ls-remote` 都可能失败，
所以别只看命令有没有报错。可靠的信号是
`git reflog show origin/master` 里出现 `update by push`，
以及 `git rev-list --left-right --count origin/master...master` 返回 `0  0`。

## 七、已知缺口（如实记录，含未验证项）

1. **银行类年报指标覆盖偏低** —— 民生 6/12、招商 7/12，属模板差异，非 bug
2. **`source=statement` 的值仍不可全信** —— 已修好并加了证据闸，但
   `data/metrics/metrics_wide.csv` 里**已知仍有少量错值**。
   它现在只用于评测与排序，**不要当权威财务数据引用**
3. **`净利润` 的 100/100 含口径假设**（归母兜底），见第五节
4. **`data/parsed/` 占 5.8 GB** —— 已提供清理脚本，需要时手动跑
   （用户明确表示**暂时不清理**，要留作回溯复核）
5. **表格 chunk 仅 6% 关联到财务指标** —— 其余是业务类表格
6. **超长表格按 12000 字截断** —— 理想做法是换摘要
7. **检索 top-1 为 80.6%（100 家规模）** —— 未继续调，因为 top-5 已 100%，
   而继续在同批数据上调只会过拟合
8. **公司名匹配未处理简称与集合称谓** —— 「浦发」这类简称、
   「四大行」这类集合词都认不出
9. **`净利润` 观测数比 `归母净利润` 少 53 条**（三年累计 253 vs 306）——
   未逐份核实是模板合并披露还是抽取漏项
10. **`扣非加权平均净资产收益率` 没进自动评测** —— `08_eval.py` 的 `SKIP` 把它排除，
    因为它没有出题模板。**这 95 家该指标是否检索得到，目前没有实测证据**
